## Blocker 2 — `pipelineOverride` vertex-layout safety check

`src/Renderer/PipelineHandle.h` — added `std::hash<gte::PipelineHandle>`
specialization (mirrors `Entity`'s own, `ECS/Entity.h`).

`src/Game/RenderSystem.h` — two new private, never-cleared
`std::unordered_set<PipelineHandle>` members (`m_warnedBadOverrideHandles`,
`m_warnedVertexLayoutMismatchHandles`), documented as single-threaded-only (`Draw()`
has no concurrent call sites today). `pipelineOverride`'s own doc comment rewritten
compact — the old "NOT automatically checked" claim is gone (it's checked now), and
the domain-specific "shadow-map/depth-prepass/GI-voxelize" worked example was
replaced with "a depth-only/alternate-shader pass" per the prerequisite spec's own
purity-rule follow-up note.

`src/Game/RenderSystem.cpp`'s `Draw()` (`Mat4&` overload):
- The pre-existing "override does not resolve" warning is now logged at most once
  per distinct handle (`m_warnedBadOverrideHandles.insert(...).second` guard),
  instead of unconditionally every call.
- New: each entity's *original* pipeline is resolved unconditionally (not just when
  there's no override), and an override whose `VertexLayoutKind()` does not match
  that entity's own pipeline is skipped — never drawn through a mismatched Pipeline.
- New warning for "some entities skipped due to vertex-layout mismatch", also logged
  at most once per distinct override handle.

Tests added:
- `tests/Game/RenderSystemDrawPipelineOverrideTests.cpp` — two new cases:
  `MismatchedVertexLayoutOverrideSkipsOnlyMismatchedEntitiesAndLogsOnce` (one
  `PositionNormal`-pipeline entity skipped, one `PositionColor`-pipeline entity
  still drawn through the `PositionColor` override, exactly one warning) and
  `RepeatedDrawCallsWithTheSameBadOverrideLogExactlyOneWarningTotal` (same
  never-registered handle across 3 consecutive `Draw()` calls, exactly one warning
  total). A `MakeColorQuadMesh()`/`MakePositionColorPipeline()` pair was added
  alongside the existing `MakeQuadMesh()`/`MakePositionNormalPipeline()` so the
  mismatch test submits a genuinely layout-matched Mesh+Pipeline pair for its
  "still draws" entity (`Shaders/Triangle.vert/frag`, the engine's own
  `VertexLayout::PositionColor` pair — see `tests/Renderer/PipelineTests.cpp`'s own
  precedent) rather than a layout mismatch the real Vulkan validation would
  legitimately reject.
- `tests/Renderer/PipelineHandleTests.cpp` (new file) —
  `PipelineHandleIsUsableAsAnUnorderedSetKey` plus two direct hash-distinguishes/
  hash-treats-equal-as-equal cases.
- Both registered in `tests/CMakeLists.txt`.
